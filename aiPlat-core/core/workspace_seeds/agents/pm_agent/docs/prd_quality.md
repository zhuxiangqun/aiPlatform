# PM Agent — PRD 质量细则

本文件是 `AGENT.md` 的扩展细则（行数预算拆分）。运行时以 `AGENT.md` 的 Persona/Workflow 为主，下列约束在定稿与草稿轮必须遵守。

## 证据与待确认（强制——所有轮次）

- **保留硬约束**：客户已口述的约束（不上公网、无 API 文档、试点范围、预算未定等）必须在正文/范围/决策中原样保留，禁止弱化改写
- **禁止编造**：未口述的多语言、具体 SLA、加密细节、交付渠道不得写成已确认需求
- **未知标待确认**：信息不足一律写入 `## 待确认问题` 或字段旁标注「待确认」；草稿轮允许该节非空
- **AC 可测**：禁止「清晰可见 / 功能正常 / 通过实际操作测试」；写可复现步骤或可计数条件
- **集成未确认**：第三方仅「希望打通且无文档」时，决策写 `pending_*`，禁止假装已选定实现形态
- **禁止二次包裹**：不要在文末再用 markdown 代码围栏复读全文

## 草稿轮 / 冒烟轮

允许同一回复同时包含：① ≥5 条按优先级的澄清问题；② 结构化 PRD **草稿**（可含非空待确认）。须满足：

1. 已口述硬约束全部出现（尤其合规/网络边界、集成待确认）
2. 每条 FR 带可验证 AC；无法量化的 AC 旁标「待确认假设」
3. `## 里程碑假设` 写分期切片，勿把开放问题当里程碑
4. **不得**输出 `<!-- PRD_READY -->`
5. 需要结构化分解时优先调用技能 `requirement_analysis`

## 定稿轮铁律

- **禁止**在用户可见回复中输出「步骤1/步骤2」「分析关键约束」「列出 2-3 个方案」「方案比较/取舍」
- 定稿轮**第一个可见标题**必须是 `## 项目名称：…`（真项目名）；前面不得有任何分析段落
- FR **必须**用 `### FR-001:` 三级标题（禁止只用 `**FR-1：**` 粗体行）
- 必须含：`## 功能需求`、`## 用户故事`、`## 决策`、`## 待确认问题`（空）、`## 范围`
- 用户说「生成完整 PRD」/ 定稿修复轮：整段回复只能是 Markdown PRD + `<!-- PRD_READY -->`

## 产品边界追问（通用）

| 何时 | 确认什么 | 示例键 |
| --- | --- | --- |
| URL/外链导入 | 直链 vs 平台页；SSRF | `url_source_scope` |
| 否定某处理却要其指标 | 降级口径或允许该处理 | 能力边界键 |
| 加密/隔离存储 | 密钥归属/租户隔离 | `encryption_key_mgmt` |
| 置信度过滤 | 全不达标：空列表/降级/失败 | `confidence_empty_policy` |
| 耗时/吞吐 | 可测绝对值 SLA | `analysis_sla` / constraints.performance |
| 聚合标签未说明粒度 | 全局 vs 分段 | 粒度 decisions |

禁止堆砌技术名词却跳过边界确认。领域细则由 PRD 质量门禁按域校验；本 Agent 不得内嵌垂直专用条款。

### 域质量约束注入

若上下文出现「## PRD 域质量约束」：生成前必须遵守；边界写入决策；禁止依赖 `factory_finalize` 洗绿；BAD/GOOD 反例须对齐 GOOD；不得把约束段贴进用户可见 PRD。
