# ADR-08 部署拆分门槛（Gate3 前定稿）

- **状态**：**Accepted（有条件）** · 2026-10-24  
- **关联**：落地方案 v1.3 §10 · `GATE3_DECISION.md` · `D13_CUSTOMER_ENDORSEMENT.md`  
- **决策人**：架构决策 owner × 业务场景 owner（兼任联签）

## 上下文

五产品可组合 ≠ 立刻多进程/多库。Gate2 已完成 facade/模块化边；Gate3 要求真实驱动 + 成本/运维评估，且无 owner/on-call 不拆。

## 决策

1. **允许**将 **Pi Thin 运行时**作为首个独立部署试点（独立进程/容器、独立运行密钥与发布节奏）。  
2. **控制面仍默认 aiPlat**；Bundle 发布与诊断证据接入不随本 ADR 拆出。  
3. **禁止**借 Gate3 默示拆：本体服务、FDE 工作台、诊断全功能中台、aiPlat 控制面拆库。  
4. 扩大拆分须新 ADR 修订 + 架构×业务联签；本 ADR 不预估完成日。

## 备选（未采纳）

| 备选 | 未选原因 |
|------|----------|
| 维持共部署、永不拆 | 无法验证独立 SLA/密钥隔离；与用户批准 Gate3 冲突 |
| 五产品一次全拆 | 爆破半径过大；§10 多项驱动未齐；违反小步 |

## §10 驱动（本批成立项）

| 驱动 | 本批 |
|------|:----:|
| 客户隔离/数据驻留/独立密钥 | ✅ Pi Thin 运行密钥与控制面分离（试点） |
| 独立扩缩容负载 | ⬜ 仍未闭合（见 `ADR09_S10_DRIVER_CLOSURE.md`） |
| 独立 SLA 与发布节奏 + 责任团队 | ✅ 试点节奏；R=运维兼任（见 ROLES） |
| ≥2 真实消费者多平台复用 | ✅ **2026-10-24 闭合**（D13 + Gate3 试点路径；`ADR09_S10_DRIVER_CLOSURE.md` §2） |
| 共享部署可量化故障 | ✅ **2026-10-24 闭合**（ROLLBACK / pilot 退出码；`ADR09_S10_DRIVER_CLOSURE.md` §1） |

至少一项真实驱动已满足（密钥隔离 + 发布节奏）。

## 成本 / 运维最小评估

| 项 | 结论 |
|----|------|
| Owner / on-call | 运维 owner（架构兼任）覆盖试点；无独立 7×24 承诺 |
| 迁移 | 试点环境并行；默认开发路径可仍共置直至试点切换清单勾齐 |
| 回滚 | **Bundle 版本回滚优先**；Runtime 镜像/进程回滚为备选 |
| API 兼容 | Thin 契约不变；不改 Bundle 字段语义 |
| 故障隔离 | 试点故障不得要求改 aiPlat 生产默认路径 |
| SLO / 备份 | 试点：进程存活 + 证据落盘；无独立备份 SLA |

## 影响

- 启用 `GATE3_PI_THIN_PILOT.md` 边界。  
- SCENE 已升格客户路径；D13 背书约束同意范围。  

## 迁移 / 回滚

- 迁移：仅试点清单内路径；禁止搬仓。  
- 回滚：停试点进程，切回共部署 Thin；保留文书。  

## 重评触发

第二产品拆分；要求独立 DB；对外 E4；on-call 空缺；§10 其他驱动成为阻塞。
