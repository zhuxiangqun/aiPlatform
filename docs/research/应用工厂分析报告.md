# aiPlat 应用工厂（AI App Factory）全面分析报告（2026-08-22）

> **对象**：管理端 `/app/factory`（前端 AIFactory 三模式容器）+ 后端 `aiPlat-platform/builder/`（builder_project_service 2189 行 + builder_session + builder_team_service）+ core 执行链（`create_pipeline_session` → PipelineEngine + team_planner + 引擎 skills）。
> **方法**：全链路代码实证（前端→API→服务→core 引擎→skill→落盘→测试→部署），每节附 `文件:行号` 证据。
> **结论先行**：应用工厂是 **"AI 驱动的双模应用产线"**——`planning_agent` 按需求自动判断 **agent（配置生成）/ code（真实代码生成）** 两种模式，走同一流水线引擎（需求→PRD→组队→多阶段执行→HITL→测试→部署→预览）。**能力真实、链路完整，但有三处需要诚实标注**：pass_rate 估算、前端仍是配置式、code 模式测试覆盖依赖用例质量。

## 3. 核心机制：双模式自动路由（最重要的设计）

`planning_agent`（LLM）分析 PRD 后**先输出 `mode` 字段**（`team_planner.py:471-476`）：

```
0. First determine the application MODE and output it as a `mode` field:
   - agent: conversational / intent-understanding / multi-turn interaction
   - code: deterministic functions / clear API / performance-sensitive
   (Judge: is the core 'natural-language interaction' or 'deterministic computation/API'?
    Only these two, do not output hybrid)
```

`recommend_team_stages` 校验 `mode ∈ (agent, code)` 才接受（`:502-504`）→ `builder_project_service.py:1019` 映射固定团队模板：

| | **agent 模式**（`~/.aiplat/teams/default.yaml`） | **code 模式**（`~/.aiplat/teams/code.yaml`） |
|---|---|---|
| 需求特征 | 对话/问答/多轮交互 | 确定性计算/API/CRUD/性能敏感 |
| 核心 agent | `agent_engineer` | `programmer_agent` |
| 产出 skill | `agent_engineering` | `code_generation` |
| 产物 | AGENT.md + SKILL.md × N（Agent 配置） | **真实源代码**（`## FILE:` 格式） |
| 关键标志 | 无文件输出 | `uses_file_output: true` + `deploy_files_to_disk: true`（code.yaml:28-29） |
| 页面 | `app_page_generation`（app_page.json 协议） | 同左（前端仍配置式） |
| 测试 | test_executor（agent_conversation） | test_executor（**code_pytest**，真 pytest） |

## 4. 生命周期（后端 `builder_project_service.py` 40+ 端点）

### 4.1 对话澄清（PM 阶段）
`chat()`（`:626`）——PM agent（`core_chat`）对话，**注入知识库检索**（`sys_knowledge_retrieve` + DomainRouter 分类，`:670-700`），生成的项目自动路由到生成的 agent 应用（`_generated_agent`，`:700-712`）。

### 4.2 PRD 生成与确认
`confirm_prd()`（`:792`）——四层兜底取 PRD：会话 prd → 持久化 `confirmed_prd` → 解析 Markdown `<!-- PRD_READY -->` → LLM 自动抽取（`_extract_prd_from_chat:735`）。PRD 结构含功能需求/范围/成功指标/验收标准/ISA 对齐（`_AIPLAT_PRD_SECTION_*`，`:57-62`）。确认后 phase: dialogue → executing。

### 4.3 自动组队
`recommend_team()`（`:951`）——delegate 到 core `team_planner.recommend_team_stages`（AI 推断 + **注入 Agent 历史性能表**：first_pass_rate/rejection_rate/qa_rollback_rate，`:970-990`）→ 按 mode 映射模板或自动建团队（`:1016-1070`）。

### 4.4 流水线执行（core 引擎）
`start_pipeline()`（`builder_session.py:151`）→ `create_pipeline_session`（CoreFacade）→ `pipeline.start(requirement, prd_data)`。阶段按 `~/.aiplat/teams/{mode}.yaml` 执行：PM→架构→（agent 工程 或 代码生成）→前端→QA→测试执行，每阶段 HITL 门（`pipeline_engine.py:4401-4408`）。

### 4.5 代码落盘（code 模式）
`code_generation` skill 输出 `## FILE:` 格式（`code_generation/SKILL.md:1-7`）→ 引擎 `_deploy_result_files`（`pipeline_engine.py:4565-4600`）解析 FILE 块写入 `~/.aiplat/apps/{project_id}/current/`（通用写文件，无业务逻辑）。**依赖必须声明在 requirements.txt**（`SKILL.md:135`，测试执行器自动 pip install）。

### 4.6 测试执行（code 模式）
`_exec_test_runner`（`pipeline_eval.py:165-185`）——读取 test_script 执行，**含 ffmpeg/ffprobe 环境依赖检查**（`_test_env_issues`，`:171-177`）→ 生成 `test_report` / `_test_pass_rate`。`test_executor` skill 分 `agent_conversation | code_pytest` 双模式（`test_executor/SKILL.md:51`），code_pytest 走 pytest SOP（`:287-291`）。

### 4.7 HITL 审批
`approve_stage`/`reject_stage`（`:1240/:1262`）——关键节点（PM 需求/架构/QA 用例，模板 `hitl: true` + `hitl_phase: review`）暂停等人审批，前端跟踪 `_hitl_stage_id`/`_hitl_output_artifact`（`Factory/index.tsx:460-467`）。

### 4.8 修复与回滚
- `start_fix`/`regenerate_stage`（`:1253/:1275`）——测试失败自动定位最大错误节点（`locate_max_error_node:1290`）+ 生成修复假设（`generate_fix_hypotheses:1306`）
- `rollback_stage`/`rollback_prd`（`:1345/:1372`）——任意阶段/PRD 回滚
- `rebuild_project`（`:1402`）——重建

### 4.9 部署
`deploy_to_app()`（`:1750`）——从 `_final_state.json` 读产物，**pass_rate 来源标注**（2026-08-22 修复）：`real_pytest`（真实测试）/ `estimated`（按产物长度估算 + 原因）→ 部署到 aiPlat-app（端口 8004，`/app/sessions/{project_id}`，`builder.py:336`）。前端 `Factory/index.tsx:425-439` 启动时检查部署状态。

## 6. 权限模型

- 全部 builder 端点走 `require_builder_access`（角色门，`builder_auth.py`）
- **创建项目/团队需 `require_admin_access`**（`builder.py:105,268`）——创建权限收紧到 admin，其余操作 builder 角色可用
- 会话/项目数据存 `~/.aiplat/` 本地（`_load_projects`/`_save_projects`），非 DB 持久化

## 7. 已知问题与诚实标注（重点）

### 7.1 pass_rate 估算水分（已修复标注，2026-08-22）
无真实测试时按产物长度估分（arch>500 字 + code>500 字 + 有测试 → 1.0）。已加 `pass_rate_source: real_pytest|estimated` + `pass_rate_estimate_reason`——**数值不再无来源，但估算值本身仍可能虚高**（字数≠质量）。

### 7.2 前端始终是配置式（两模式共用）
无论 agent/code 模式，前端都走 `app_page_generation` → app_page.json 协议 → 5 个预置组件渲染（`AppPage.tsx:115-119`：file_upload/progress_poller/result_dashboard/data_form/data_table）。**code 模式生成后端代码 + 配置式前端**，不是全栈原生代码。复杂定制 UI 做不了。

### 7.3 code 模式测试覆盖依赖用例质量
test_executor 执行的是 `test_case_generation` 生成的用例——**测试质量取决于 LLM 生成的用例好坏**；若用例本身薄弱，pytest 全绿也不代表真实可用。

### 7.4 双入口认知成本
`/app/factory`（完整）与 `/app/builder/projects`（纯列表）并存，侧边栏只露 factory，但 builder/projects 仍可直达——用户可能困惑入口差异。

### 7.5 权限不对称
创建需 admin（合理），但"已部署应用"的访问（`/app/apps`）无独立权限模型，任何 builder 角色可见全部已部署应用。

## 8. 总体评价

| 维度 | 评分 | 说明 |
|---|---|---|
| 架构 | ⭐⭐⭐⭐⭐ | 双模式自动路由 + 统一引擎 + 边界合规（全走 CoreFacade） |
| 能力真实性 | ⭐⭐⭐⭐ | 代码模式真落盘、真 pytest；agent 模式真生成 Agent 配置 |
| 工程完备度 | ⭐⭐⭐⭐⭐ | HITL/修复/回滚/重建/部署/预览全生命周期 |
| 诚实性 | ⭐⭐⭐⭐ | pass_rate 已标注来源；前端配置式/测试依赖用例质量需持续诚实 |
| 扩展性 | ⭐⭐⭐⭐ | 新团队=新 YAML 模板，零引擎改动（`team_planner.py:14` 注释） |

**一句话**：应用工厂是 aiPlat 最接近"AI 代替人做软件开发"的能力——LLM 判断需求走配置还是代码路线，真实产出可运行产物并测试部署。**能力真实、链路完整**；剩余改进点集中在"前端配置式局限、测试用例质量依赖、pass_rate 估算精度"三处，均已在文档中诚实标注。
