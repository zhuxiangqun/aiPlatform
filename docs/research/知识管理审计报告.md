# aiPlat 知识管理审计报告 v2（2026-08-19 重写：以数据元/本体/向量/wiki/RAG 五要素关系为主线）

> **对象**：`core/harness/knowledge/`（41K 行）+ `knowledge_pipeline/` + `ontology_engine/` + `syscalls/retrieval*.py` + 消费链。
> **方法**：沿"数据元 → 本体 → 向量库 → wiki 库 → RAG"关系链逐层代码追踪（写入侧 + 读取侧双向验证），每条结论附 `文件:行号`。
> **结论先行**：五要素关系**部分断裂**——① 向量知识库（`kb_embeddings`）**0 写入者 = 空壳**（向量检索空转，RAG 实际不依赖向量）；② 图存储**两套并存**（kb_graph 死 vs GraphIndex 活）；③ 本体-数据元（ABox 构建）与 wiki 知识库（主库）关系正确且活跃；④ RAG 实际走 CRAG 多级（本体图优先，非向量）。

## 2. 关系链逐段验证

### 2.1 数据元 → 本体（ABox 构建）✅ 正确且活跃

- `build_abox`（`knowledge_abox_builder.py:45`）：扫描 wiki 页面（frontmatter 解析 `_parse_frontmatter:125`）+ KB 文档（`_scan_kb_documents:159`）→ 构建实例三元组
- `_build_wiki_triples:198` / `_build_kb_triples:310`：页面字段/文档 → subject-prop-value 三元组
- `_cross_validate_sources:332`：多源交叉验证
- 消费：`orchestrated_retrieval.traverse_ontology_graph`（`retrieval_crag.py:168` 本体优先检索、`multi_agent_orchestrator.py:66`、`materials_chat.py:485`）——**本体→图谱→检索链路生产活跃**

### 2.2 数据元 → wiki 知识库 ✅ 正确（主库）

- `wiki_indexer.py:164`：写入 `indexed_artifacts`（文档→wiki 索引）
- `wiki_engine.read_page:262` / `search_pages:1626` / `wiki_structured_query`：结构化检索
- `wiki_retriever`：租户隔离（`wiki_retriever.py:310-319` 交叉校验）+ FTS5
- **注意**：wiki 页面**不进向量库**（wiki_indexer 无 kb_embeddings 写入）——wiki 检索靠 FTS5 + 结构化查询

### 2.3 数据元 → 向量知识库 ⚠️ **空壳（P0-3）**

- `sqlite_retriever.py:239` 是 `kb_embeddings` **唯一写入点**（`add()` 内部）
- **`add()`/`add_batch()` 0 生产调用者**（全仓 grep 无）；`KnowledgeRetriever.add_knowledge`（`retriever.py:325`）同样 0 调用者
- 读侧：`syscalls/retrieval.py:221` 创建 sqlite_retriever 后**只调 search 不调 add** → `_load_embeddings` 查空表 → 恒空
- **结论**：向量知识库是"声明未接线"的空壳——向量检索路径在生产中**从未有数据可查**；`sys_knowledge_retrieve` 实际靠文档 docstring 自述的"退路: sys_wiki_retrieve"工作

### 2.4 本体 → 图存储 ⚠️ 两套并存

| 图存储 | 写入 | 读取 | 状态 |
|---|---|---|---|
| `knowledge/graph.py` kb_graph | `_store_triples:92` | `graph_enhance_query:119`（syscalls/retrieval.py:195） | ⚠️ **绑定数 bug 死**（P0-2，SQL 4 占位符 vs 2 参数） |
| `ontology_engine/graph_index.py` GraphIndex | ABox/知识管线 | `orchestrated_retrieval.py:125` + `GraphRAGRetriever` | ✅ 活跃 |

- **两套图库各自独立**（schema 不同、写入者不同、无同步）——知识图谱事实被拆分，图检索可能不一致

### 2.5 RAG 实际融合路径 ✅（但不含向量）

- **CRAG 多级**（`retrieval_crag.py`）：Cache → **GraphRAG 本体图**（L144-160，`GraphRAGRetriever`，domain 非 default 时）→ **ontology_first_retrieve**（L168，本体→图遍历）→ **FTS5**（L194）→ **wiki 集合**（L302-308）→ **Deep Research web**（L374）
- 生产使用：`rag.py:109`、`materials_chat.py:570,738`——**RAG 主路径不经过向量库**（第一级就是本体图）
- `sys_knowledge_retrieve`（unified 向量）8 处调用但向量库空 → 空结果 → 退路 wiki
