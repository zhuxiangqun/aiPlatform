## 4. 发现与建议

### 4.1 安全降级观察点（需决策确认，非阻塞）

**现象（根因已定位）**：`core_facade` 导入触发 DB 初始化，DB 不可用时 `resolve_skill_permission` 不可用 → policy_gate 的 skill deny/ask 规则被 except 跳过（fail-open）。本地沙箱（AIPLAT_HOME 不可写）下，`PolicyGate.check_tool` 对配置了 `deny` 规则的 `skill_load` 返回 **ALLOW**（fail-open）；DB 可写环境下正确返回 DENY。

**分析**：PolicyGate 在权限管理基础设施（perm_mgr/DB）不可用时**降级放行**而非拒绝。这是常见的安全取舍（可用性 vs 安全性），但对企业级"deny-by-default"原则构成**fail-open 风险**——若生产环境 DB 故障，本应被 deny 的操作可能放行。

**处置（2026-08-23，方案 B 已实施）**：保持 fail-open（不改变现有策略，避免可用性回归），但加**降级审计事件**——`policy_gate.py` skill 规则分支的 except 路径记录 `execution_store.add_audit_log(action="security_degraded", kind="skill_permission_resolver_unavailable", ...)`（含 user_id/tool/skill/error 字段），每次降级放行均可追溯。
- **A（fail-closed）** 未采用（需改变默认策略，作为后续可选项保留）；
- **C（无记录降级）** 已排除——现在降级有审计痕迹。
- 验证：`test_policy_gate_skill_load_permissions.py::test_security_degraded_audit_wired`（静态接线断言，4 passed 含环境）。
