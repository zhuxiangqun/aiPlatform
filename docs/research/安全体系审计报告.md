## 4. 发现与建议

### 4.1 安全降级观察点（需决策确认，非阻塞）

**现象（根因已定位）**：`core_facade` 导入触发 DB 初始化，DB 不可用时 `resolve_skill_permission` 不可用 → policy_gate 的 skill deny/ask 规则被 except 跳过（fail-open）。本地沙箱（AIPLAT_HOME 不可写）下，`PolicyGate.check_tool` 对配置了 `deny` 规则的 `skill_load` 返回 **ALLOW**（fail-open）；DB 可写环境下正确返回 DENY。

**分析**：PolicyGate 在权限管理基础设施（perm_mgr/DB）不可用时**降级放行**而非拒绝。这是常见的安全取舍（可用性 vs 安全性），但对企业级"deny-by-default"原则构成**fail-open 风险**——若生产环境 DB 故障，本应被 deny 的操作可能放行。

**处置（2026-08-23，方案 B → 2026-10-08，方案 C 已实施）**：
- **默认仍 fail-open**（`AIPLAT_POLICY_FAIL_MODE` 缺省 `open`），避免开发/单测可用性回归。
- 降级必记审计：`security_degraded` + `fail_mode` / `critical` / `blocked`。
- **可配置**（方案 C）：
  - `AIPLAT_POLICY_FAIL_MODE=open|ask|closed` — 关键路径（`skill_load` 规则解析、带 request context 的 skill EXECUTE）降级策略。
  - `AIPLAT_POLICY_FAIL_CRITICAL_MODE` — 可选覆盖关键路径（生产可 `closed`，灰度用全局 `ask`）。
  - **非关键路径**固定 `open` + 告警（避免 DB 抖动大面积 DENY）。
  - **一键回滚**：`AIPLAT_POLICY_FAIL_MODE=open` 并清空 CRITICAL_MODE。
- 生产建议：先 `ask` 灰度 → 关键路径再升 `AIPLAT_POLICY_FAIL_CRITICAL_MODE=closed`。
- 验证：`test_policy_gate_fail_mode.py` + `test_policy_gate_skill_load_permissions.py::test_security_degraded_audit_wired`。
