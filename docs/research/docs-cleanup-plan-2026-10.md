# aiPlat / Pi 文档减量清理方案（2026-10）

> **性质**：清理**方案**（评审稿修订），不是删除授权，也不是已执行记录。  
> **基线**：[`docs-system-status-analysis-2026-10.md`](docs-system-status-analysis-2026-10.md)（现状快照）。  
> **本文件不授权**跳过逐篇复核直接删文件或整主题簇搬家。

---

## 0. 硬边界（必须遵守）

### 0.1 归档 ≠ 减总数；两项主指标 + 一项可选导航指标

主验收必须同时报告下列两项（命令、时点、口径写死；禁止只报其一）：

| 指标 | 定义 | 用途 |
|------|------|------|
| **维护区文档数** | 非归档、非约定生成物目录下的 `.md` 份数（**路径规则**见 §4；目录状态） | 评价「维护面是否收缩」；迁 archive / 排除生成物会改变此数 |
| **仓库保留文档总数** | 约定范围内全部 `.md`（默认：`docs/**/*.md` 排除 `node_modules`） | 评价「仓库是否真少了文件」；仅删除或合并去副本才会下降 |

**根目录 `reports/`（仓库根下，非 `docs/reports/`）不计入上述两个文档数量指标。**  
该目录含审计 JSON、变更日志、DOCX 等，属于处置时 **R3/R5 必须检查的依赖与留存证据范围**（见 §2.1），读者不得误以为它进入了 `docs/` 维护区或 `docs/` 总数。

可选、**不得与维护区混称**的第三项：

| 指标 | 定义 | 用途 |
|------|------|------|
| **默认导航覆盖数** | 被 `docs/README`、各簇 README「现行」索引、by-role 等**显式链到**的文档份数（导航状态） | 评价导航噪声；与维护区路径公式可能不一致，须单独成行 |

- 迁入 `archive/`：通常降低**维护区**（及可能降低导航覆盖）；**总数可以不变**。  
- 物理删除 / 合并去副本：才可能降低**总数**。  
- 禁止再用模糊的「活跃区」一词同时指导航状态与目录状态；旧称「活跃区」在本修订中拆成上表。

### 0.2 主题相同 ≠ 重复

同一产品故事可以合法分摊到：

| 类型 | 典型位置 | 减量时默认 |
|------|----------|------------|
| 规范 / 契约 | `contracts/`、architecture contract | **保留**（除非被取代或失效） |
| 操作指南 | `manuals/` | **保留**（除非步骤失效、或责任已由具名文件接替） |
| 目标 / 规划 | `architecture/plans/` | 可降权或归档；**不因主题与契约相同而删** |
| 研究 / 审计快照 | `research/` | 收官且无现行责任后，优先退出维护区 |

减量证据只能是下列之一（可并列），**不能**按「FDE 簇 / 对标簇 / 本体簇」整包删：

1. **重复正文**：多份文档大段粘贴同一叙述，且可收敛到单一权威源 + 链接。  
2. **已被取代**：正文或索引已声明被另一文件取代（或可核验的取代关系）。  
3. **失效操作步骤**：命令/路径/流程与现行代码或手册冲突且无留存价值。  
4. **无留存价值的快照**：一次性核实/冒烟/签收过程纸，且无合规/审计留存要求（需人工判定；**可不要求替代文档**，见 §2 删除双路径）。

### 0.3 候选 ≠ 删除清单

基线曾写「约 18 份收官」；C0 冻结集合见 §8.5.1（**20** 份文件名清单，未复核）。「入链次数」「同名近重」同为**待逐篇复核的候选**，非删除授权。

已知方法限制：

- 文件名字符串命中：可能漏相对路径别名、代码内路径、外部 Wiki/工单入口。  
- 关键词（已收官/已完成等）：只能发现候选，**不能代替逐篇判读**。

任一文件在执行「迁 archive / 合并 / 删除」前，必须完成 §2 复核表并留下简短记录（可记在本方案附录或 PR 描述）。

### 0.4 与导航治理的关系

导航改进与文档减量**可以同时成立**，职责分开：

- **导航**：让读者找到现行权威（不在本方案重复扩 scope）。  
- **本方案**：降低维护区噪声，并在有证据时降低仓库总数；可选另报导航覆盖数。

### 0.5 已完成过程材料 ≠ 可自动迁档

功能「已落地 / 已收官」不等于文档无责任。若文档仍承担下列任一**现行责任**，则 R6 不得仅为「已实施」或「低入链」而迁 archive / 删除，除非 R4 写明**接替文件**：

- 现行操作步骤（用户/运维仍按此执行）  
- 验收 / 签收 / 复现依据  
- 仍生效的约束正文（契约条款本身，而非一次性开工勾选纸）

contracts 须区分：

| 子类 | 例子（示意） | 默认 |
|------|--------------|------|
| **约束正文** | 仍被引用的 Workbench Contract、Runtime Authority 等 | 留在维护区 |
| **阶段 / 过程留存** | PHASE 开工清单、某 WAVE 过程 charter、一次性冒烟记录 | 复核后可迁 archive 或索引降为「过程留存」 |
| **签收证据** | M4 签收包等 | 有留存义务则保留（维护区或 archive 均可，但**不可删**除非 R5 明确无义务） |

## 1. 目标与非目标

### 1.1 目标

1. 降低 **维护区文档数**（优先：`docs/research/` 收官且无现行责任的稿退出维护区）。  
2. 在有 §0.2 证据时，通过合并同名近重或删除无价值快照，降低 **仓库保留总数**（次优先，更严）。  
3. 每次批次可复现：**维护区 + 仓库总数**（可选附导航覆盖）+ 复核记录。

### 1.2 非目标

- 不整包删除 FDE / 对标 / 本体主题下的全部文件。  
- 不重写 CAPABILITIES、不改子仓 `*/docs` 大规模搬迁（除非单独立项）。  
- 不把五产品规划伪删成「未发生」；目标态文档可归档或降权，不可冒充无历史。  
- 不把本方案当成已经完成的清理。

## 2. 逐篇复核流程（执行前强制）

对每个候选文件填写（可缩为 PR checklist）：

| # | 检查项 | 通过标准 |
|---|--------|----------|
| R1 | 文档类型 | 规约 / 指南 / 规划 / **裁决（ADR）** / 报告快照 / 过程纸 / 模板 / 索引 / 其它（见 §2.0） |
| R2 | 现行责任 | 是否仍承担操作、验收、复现、约束正文或 **ADR 决策效力** 责任；若是，接替文件是谁（无接替则不得迁/删） |
| R3 | 入链普查 | Markdown 文件名/别名；**以及** JSON/DOCX/变更日志/生成脚本/代码/`packages`/外部留存要求（见 §2.1）；未知项记法见 §2.3 |
| R4 | 取代关系 | 是否已有权威替代；替代是否写明（删除路径 A 需要；路径 B 不强制有替代） |
| R5 | 留存义务 | 合规、签收、事故/审计追溯是否需要保留全文；未知项记法见 §2.3 |
| R6 | 处置决定 | **保留维护区** / **迁 archive** / **合并后删副本** / **删除**（删除须满足 §2.2 双路径之一） |
| R7 | 指标影响 | 预计影响维护区？仓库总数？导航覆盖（若测）？ |

处置默认优先级：

1. **保留维护区**（无证据，或仍有现行责任且无接替）  
2. **迁 archive**（收官/过程留存仍有价值，且现行责任已接替或本无现行责任）→ 降维护区，总数通常不变  
3. **合并去重**（同名近重且可证重复正文或可证单一权威）→ 可能降总数  
4. **删除**（§2.2）→ 降总数；最严，默认少用

### 2.0 R1 类型与责任判断（对齐 DOCUMENT_SYSTEM）

`DOCUMENT_SYSTEM` 将 **裁决（Decision/ADR）** 列为长期留存类型。R1 选用下表，避免把永久决策误归为普通规划或过程纸：

| R1 类型 | 典型位置 / 例子 | 现行责任怎么判（R2） |
|---------|-----------------|----------------------|
| 规约 | CLAUDE、boundary、standards | 仍约束行为 → 维护区 |
| 指南 | manuals | 仍被按步骤执行 → 维护区；责任已接替才可迁 |
| 规划 | architecture/plans 多数 | 目标态/历史规划；无操作责任时可迁 archive |
| **裁决 / ADR** | `architecture/decisions/*` 等 | **默认长期留存于维护区**；仅当决策被明示推翻且接替 ADR/契约已就位，才可迁 archive；**默认不删** |
| 报告快照 | research 审计、部分 reports | 收官且无验收/复现责任 → 可迁 archive |
| 过程纸 | PHASE 清单、WAVE 过程记录 | 非约束正文；可迁 archive / 索引降权 |
| 模板 | `*_TEMPLATE.md`、空商务模板 | 仍被开工/交付引用 → 维护区；废弃模板可迁 |
| 索引 | 各簇 README、by-role index | 导航职责；不因「同名」进 C2 合并队列 |

### 2.1 R3/R5 不得只查 Markdown：两处 `reports` 反例

须区分：

| 路径 | 是否计入维护区 / `docs/` 总数 | 处置时 |
|------|------------------------------|--------|
| **`docs/reports/`** | 计入 **仓库总数**；是否计入 **维护区** 由 C0 按 §4 清单决定，**禁止仅凭目录标签一刀切** | R3/R5 查生成约定与手工维护属性 |
| **仓库根 `reports/`** | **不计入**本方案两个数量指标 | R3/R5 **必须**检查：`audit_findings*.json`、`audit_changelog*.md`、复审 DOCX、相关生成/审计脚本与外部留存要求 |

[`docs/reports/README.md`](../reports/README.md) 将目录概括为自动生成快照，但清单中 `AIPLAT_ARCHITECTURE_REPORT.md` 又标为「手动整理综合架构报告」——目录标签不可靠。

根目录 `reports/README` 或变更日志若暗示「删除不影响完整性」，**禁止**据此批量删除；须按本表做 R3/R5。

### 2.2 删除双路径（与 §0.2 对齐）

R6=**删除**时，必须满足下列**之一**（并完成入链处理与 R5）：

**路径 A — 有明确替代文档**

1. R4 核实取代关系（权威源写明或可核验）；  
2. 入链已迁到替代文档（含 §2.1 非 Markdown 引用）；  
3. R5 确认无单独留存义务（或义务已由替代/archive 副本承担）。

**路径 B — 无替代文档**

1. 证明属于 §0.2 第 4 类「无留存价值的一次性快照」；  
2. 无入链，或入链已全部改为说明「已移除」/指向其它现行材料；  
3. R5 确认无合规或审计保留要求。

两条路径均适用「删除最严、默认少用」；路径 B 不得用「主题已过时」一笔带过。R5 若为「未核实/待确认」，**不得**视为已满足本条「确认无义务」。

### 2.3 未知项记录规则（R3 / R5）

仓库内无法核实的引用或留存义务，**必须**在复核表记为 **`未核实` / `待确认`**，并简述缺口（如：外链不可达、外部系统权限不足、合规政策未书面确认）。

| 禁止 | 要求 |
|------|------|
| 把未核实项写成「确认无需改」 | 仅仓库内已核对、确无引用处可标「确认无需改」 |
| 把未核实的留存义务默认成「无义务」 | R5 未核实期间 **不得** 据此推进删除；迁 archive 须在复核表显式注明「R5 未核实，仅按当前已知证据迁档，留存义务待确认」或先搁置 |
| 验收时把「未核实」折算为已关闭 | 批次关闭前，未核实项须保留为开放项，或取得书面确认后再改状态 |

## 3. 批次划分

### 批次 C0 — 度量口径冻结（**C1–C4 执行前置条件**）

**必须完成（阻塞后续批次）：**

1. 冻结 §4 **维护区**路径公式与对应统计命令（含 §4.1 对 `docs/reports/` 的 **A 或 B** 选择及核实记录）；  
2. 冻结 **仓库总数**范围与命令（确认 **不含** 根目录 `reports/`）；  
3. 宣布是否测量 **默认导航覆盖数**（若测，单独命令；不与维护区混名）；  
4. 冻结候选表版本（research 收官候选、C2 同名对），每条标注「未复核」；  
5. 书面确认：根目录 `reports/` 仅作 R3/R5 证据范围，不进入两项数量指标。

**可选：** 将上述数字与命令输出落盘到附录或独立 snapshot 文件。

C0 **不是**「整批可选」；仅「数字是否另存文件」可选。未完成 C0 口径冻结，不得开 C1。

### 批次 C1 — research 收官候选复核（只迁 archive，不删）

- **执行状态（2026-10-23）**：**已执行** — 复核表 [`c1-archive-review-2026-10-23.md`](c1-archive-review-2026-10-23.md)；**17 迁 archive / 3 保留**；删除 0。保留：`aiPlat治理体系元审计报告.md`、`企业级AI可信落地全景图-aiPlat对照.md`、`应用工厂分析报告.md`。  
- **输入**：§8.5.1 冻结的 **20** 份文件名清单（未复核；非迁档授权）。优先复核入链偏低者，**不**把低入链当作充分条件。  
- **动作**：逐篇 R1–R7 → 仅当 R6=迁 archive（现行责任已接替或本无现行责任）时迁入 `docs/archive/`。迁档时须同时完成：  
  1. 更新 `research/README` 与 `archive/README`；  
  2. **按 R3 普查结果，修复所有指向该文档的引用**（Markdown 链接/路径字符串，以及 §2.1 范围内的 JSON/DOCX/变更日志/脚本/代码等，凡仓库内可改处）；  
  3. **修复迁档后该文档内部的相对链接**（因目录层级变化而失效的 `../`、同级相对路径等）。  
  不得只改两份 README 即视为迁档完成。  
- **禁止**：未复核整表搬家；因「主题是审计」或「已收官关键词」整目录归档；把仍作验收/复现依据的报告当过程纸迁走。  
- **验收**（缺一不可）：  
  1. 维护区下降（或 research 维护子集下降）有命令证据；仓库总数不变（除非另有已批准的删除）；PR 附 C0 同口径前后对比；  
  2. PR 附该篇 R3 入链清单，并标明每条引用的处置（已改路径 / 已改指向接替文 / 确认无需改 / **未核实·待确认**）；禁止把未核实项记成「确认无需改」（见 §2.3）；  
  3. **单篇**：迁档后该文件内、指向仓库路径的相对链接**全部**可解析，或已更新为有效路径（与动作第 3 点同强度；不得以抽检代替全量核对）；  
  4. **批次级（本批全部拟迁档篇目完成迁档后强制）**：对本批**已迁入** `docs/archive/` 的文档再统一跑一遍相对链接核对——覆盖后续迁档导致先前迁入文的链接目标失效的情况；单篇通过**不能**代替本条。批次关闭前须附统一复查通过证据（或未关闭的失效链接清单与修复提交）。
