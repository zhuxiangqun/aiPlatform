# E4 管理端 Core 文档边界

## 1. 结论

`aiPlat-management/docs/core/` 的 8 份文档不是 `aiPlat-core/docs/` 的简单副本。

它们的真实角色是：

```text
管理端操作/UI 文档
```

而 core 文档的角色是：

```text
引擎机制/实现/契约
```

因此不应按“重复文档”合并，也不应只写“派生摘要”。

## 2. 文档清单

| 管理端文档 | 行数 | 角色 |
|---|---:|---|
| `adapters.md` | 543 | 适配器管理界面与操作 |
| `agents.md` | 623 | Agent 生命周期管理 |
| `harness.md` | 503 | 执行引擎运维 |
| `index.md` | 485 | 核心能力层管理入口 |
| `knowledge.md` | 452 | 知识库管理 |
| `learning.md` | 87 | Runs / Artifacts 浏览 |
| `memory.md` | 424 | 记忆系统管理 |
| `skills.md` | 661 | Skill 注册与执行管理 |

这些文档包含大量：

- 管理端页面/菜单；
- 操作流程；
- 权限/租户视角；
- 运维步骤。

core 文档不包含这些内容。

## 3. 处理

不合并正文，改为明确边界：

```text
管理端操作/UI → 本文
引擎机制/契约 → aiPlat-core/docs/
```

每份文首已从“派生文档”改为“管理端视角（E4）”。

## 4. 后续

如果未来要减少重复：

- 管理端文档只保留页面/流程/权限；
- 机制说明改为链接 core；
- 不复制 core 的架构和算法。
