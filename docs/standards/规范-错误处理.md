# 规范-错误处理

> 状态：v1.0 (2026-08-16) · 适用：全部 Python 代码 · 来源：规范体系审计 P2-B3（496 处历史 except 吞错已治理，需规范固化）

## 1. 禁止静默吞错（强制）

**禁止** `except Exception: pass` 无日志、无 `# noqa:` 豁免（守卫 §5.68 阻断新增，基线 0）：

| ❌ 禁止 | ✅ 应做 |
|--------|--------|
| `except Exception: pass` | 至少 `logging.debug(str(e), exc_info=True)` |
| `except Exception: pass  # noqa` 无理由 | 合法豁免必须标注 `# noqa: <模式>` |

## 2. 豁免白名单（允许静默）

以下异常模式是合法忽略，必须带 `# noqa:` 注释：

| 模式 | 理由 |
|------|------|
| `ImportError` / `ModuleNotFoundError` | 可选依赖探测 |
| `OSError` / `PermissionError` | 文件/权限探测 |
| `sqlite3.OperationalError` | 迁移幂等（`# noqa: schema-idempotent`） |
| `asyncio.CancelledError` | 任务取消正常路径 |
| `WebSocketDisconnect` | 客户端断开正常 |

## 3. 错误日志级别

| 场景 | 级别 | 示例 |
|------|------|------|
| 可恢复降级 | `debug` | 缓存 miss、可选组件缺失 |
| 影响单次请求 | `warning` | 单条数据处理失败 |
| 服务级故障 | `error` | DB 连接失败、不可恢复状态 |

## 4. 异常链

- 必须保留 `raise ... from e` 或 `exc_info=True`（不丢失原始 traceback）
- 禁止 `except: raise` 裸吞后重新抛无信息异常
