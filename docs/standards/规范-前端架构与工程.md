# 规范-前端架构与工程（TypeScript / React）


## 1. 架构分层

前端采用 **服务层 / UI 组件层 / 页面层** 三层结构，禁止跨层直连：

| 层 | 目录 | 职责 | 禁止 |
|----|------|------|------|
| 服务层 | `frontend/src/services/` | API 调用、类型定义、数据转换 | 直接 `fetch` 散落页面 |
| UI 组件层 | `frontend/src/components/` | 可复用组件、通用 UI 原子（`components/ui/`） | 页面业务逻辑混入组件 |
| 页面层 | `frontend/src/pages/` | 路由页面、页面状态编排 | 直接操作后端 API |

## 2. 服务层统一出口（强制）

- **禁止**直接从 `services/coreApi.ts` 等具体文件引用（会形成高 in-degree 枢纽）
- **必须**统一从 `services/index.ts` 引用 API 与 types：
  ```ts
  import { workspaceAgentApi } from '../services'
  ```
- 新增 API 封装：在对应模块 service 文件实现，经 `services/index.ts` re-export

## 3. UI 统一出口（强制）

- UI 相关（toast / gateError 等）**必须**从 `components/ui` barrel 引入
- **禁止** `import { ChatWidget } from '../../components/ui/ChatWidget'` 这类直接子文件引用
- 原因：避免非聚合点高枢纽、便于统一主题/改造

## 4. API 调用规范

| 规则 | 说明 |
|------|------|
| **路径必须与后端注册路由一致** | 前端 `fetch()` 路径必须能在后端找到对应 `@router.*`（CI 守卫 §44/§45 自动校验） |
| **Base URL 统一** | 通过 `vite.config.ts` proxy 或统一 API client，禁止页面硬编码端口 |
| **错误处理** | 必须处理非 2xx：展示 `gateError` envelope 或统一错误提示，禁止静默 |
| **响应类型** | 使用后端 `response_model` 对应的 TS 类型，禁止 `as any` 绕过 |

## 5. 状态管理

- 页面级状态：React 内置 state / reducer
- 跨页面共享状态：集中 store（如 zustand/redux），禁止全局变量散布
- **配置驱动**：对流水线产物判断依据**结构特征**（`'recommendation' in val`）而非硬编码 artifact key（`key === 'test_report'`）

## 6. 工程约束

| 规则 | 说明 |
|------|------|
| 类型安全 | 禁止 `any` 逃逸（lint 强制）；`tsc --noEmit` 必须通过 |
| 组件粒度 | 单文件 ≤ 400 行；超限拆分子组件 |
| 依赖 | 禁止引入未确认的新 npm 包 |
| 构建 | `npm run build` 必须通过（CI 门禁） |
| 路径 | 禁止 `fetch('/api/core/...')` 直连 core 端口，经 proxy 转发 |

## 7. 验证命令

```bash
cd aiPlat-management/frontend && npx tsc --noEmit    # 类型检查
cd aiPlat-management/frontend && npm run build       # 构建
bash scripts/architecture_guard.sh                    # §44/45 跨语言契约 + 代理路由
```
