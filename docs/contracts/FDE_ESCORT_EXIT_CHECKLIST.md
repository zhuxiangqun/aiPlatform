## 0. 退出原则

护航退出**不是时间到了就退**，而是**条件满足才退**。

- 全部 A/B/C/D 组勾选完成，方可评估退出。
- 任一组未达标，延长护航，并记录阻塞项与新的评估日期。
- 退出不等于结束支持，而是从「FDE 主导」转为「客户主导 + 平台监控」。
- 「首月护航」仅作默认日历提示；**以本清单为准**。

## A. 客户独立操作能力

- [ ] 客户管理员已完成 ≥ _N_ 次独立 Action 执行（建议 N=10）
- [ ] 客户侧已独立处理 ≥ _M_ 次异常（建议 M=3）
- [ ] 客户侧已独立完成 ≥ _K_ 次签收 / 归档流程（建议 K=2）
- [ ] 客户侧联系人已明确，且非单点依赖（≥2 人）

**证据：** _审计记录 / 培训记录 / 工单系统_

---

## B. 平台侧稳定性

- [ ] 质量分连续 _X_ 天达标（建议 X=30，阈值 _Q_）
- [ ] Action 成功率连续 _X_ 天 ≥ _Y%_（建议 Y=95%；成功态见使用信号最小集）
- [ ] 审计完整率达标（按 audit.v1 必填字段）
- [ ] 无未处理的高危 canary 异常
- [ ] Evolve 回滚率 ≤ _Z%_（若已启用；未启用写 N/A）

**证据：** `_/quality-summary` · `action_audit` · canary API · Evolve metrics_

---

## C. 使用信号

- [ ] 日活操作人数（S1）≥ _N_（建议 N=2）
- [ ] Action 日调用量（S2）≥ _M_（建议 M=基线 70%）
- [ ] 手工旁路率 ≤ _X%_（建议 X=20%，若客户侧可观测；否则 `not-available`）
- [ ] 客户侧登录频率 ≥ _K_/周（建议 K=3；不可观测则 `not-available`）

**证据：** [`FDE_USAGE_SIGNAL_MINIMAL_SET.md`](./FDE_USAGE_SIGNAL_MINIMAL_SET.md) · 客户侧数据

**说明：** 平台侧 S1/S2（及可选 S3/S4）可自动读取。客户侧两项标 `not-available` 时**不阻塞退出**，但须在 §D / §E 记录。
