**1.3.3 测试用例**：

```
输入：
"请分析以下标书文本：某市项目共4家投标人。A报价150万，B报价149.8万，
C报价149.5万，D报价148万。4家投标文件中均出现相同的'2024年12月30日'
错误（招标文件要求2025年3月30日）。A、B、C的保证金均从同一银行相邻账号汇出。"

预期输出：
### 报价一致性 → 判定：是
### 文件雷同 → 判定：是
### 保证金来源 → 判定：可疑
综合判定 → 风险等级：高
```

### 1.4 现场 Demo（标准 5 步演示）

| 步 | 演示内容 | FDE 操作 | 客户看到 |
|:---:|------|------|------|
| **1** | 打开应用 | 打开管理端 → 终端使用 → 工作台 | 登录页面 |
| **2** | 选择 Agent | 选择"标书助手" | Agent 名称和描述 |
| **3** | 输入标书 | 粘贴准备好的标书文本 | 文本输入框 |
| **4** | 等待分析 | 点击发送 / 回车 | 进度指示器。实际耗时取决于客户机器 CPU 性能，3B 模型推理约 30-40 秒 |
| **5** | 查看报告 | 展示输出 | 逐项检查结果 + 综合判定 + 建议措施 |

> **⚠️ 数据格式限制**：标书助手是纯文本推理 Agent。如表书含表格或图片，FDE 需在现场**提前将关键数据手动录入为文本格式**（如"A 公司报价 150 万，B 公司 149.8 万..."）。如需 OCR 全自动化，需后续定制开发（追加 OCR 数据处理能力）。

> **⚠️ 输出稳定性**：标书助手的 `temperature` 已设定为 `0.0`，确保同一输入多次分析结论一致。Demo 前请确认此配置已生效。

### 2.3 应用交付方式选择

| 方式 | 路径 | 操作 | 适用场景 | 推荐指数 |
|:---:|------|------|------|:---:|
| **A: 工作台直接使用** | 终端使用 → 工作台 | 用户选择"标书助手"对话 | 内部小团队（<5 人），无需定制 UI | ⭐⭐⭐ |
| **B: App Studio 独立应用** | App Studio → 创建新项目 → 绑定标书助手 → 一键部署 | Studio 对话式创建 → 自动生成独立页面 | 需要独立品牌应用入口，非技术人员使用 | ⭐⭐⭐⭐⭐ |
| **C: API 端点集成** | 渠道管理 → 新建 API 渠道 → 生成 API Key | 客户系统 POST 到 `/api/v1/agents/标书助手/execute` | 客户已有业务系统，需对接 | ⭐⭐⭐⭐ |

> **推荐方式 B**：App Studio 一键生成独立页面，零开发成本，客户获得完整的品牌化应用入口。

## 5. 常见问题与处理

| # | 问题 | 原因 | 处理 |
|---|------|------|------|
| Q1 | Agent 输出格式不一致 | temperature 未设为 0.0 | 确认 AGENT.md config 中 `temperature: 0.0` |
| Q2 | 标书含表格时报错 | 纯文本 Agent 无法处理结构化数据 | 手动将表格转为文字描述后重新输入 |
| Q3 | Agent 超时（>180s） | 模型推理过慢 | 确认使用的是 qwen2.5:3b（非 7B），单次 ~35s |
| Q4 | 客户无法登录管理端 | 未注册用户 | Admin → 认证鉴权 → 创建用户 |
| Q5 | 灰度期间 Agent 异常 | 配置错误或模型异常 | Tab 7 → 一键回滚，检查日志后重新上线 |
| Q6 | 离线部署包无法启动 | 依赖缺失或权限问题 | 检查 `install.sh` 输出日志。常见原因：端口 8000 被占用 → 修改 `docker-compose.yml` ports 映射 |
