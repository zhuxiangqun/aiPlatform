## 0. POC 是什么

POC (Proof of Concept / 概念验证) 是 FDE 在客户现场展示 aiPlat 价值的最快方式。
**不要追求生产级完整度**——追求速度 + 客户真实数据的即时效果。

## 1. 时间预算

| 场景 | 总时间 | 适用条件 |
|------|:--:|------|
| **轻 POC**（只用一个 Skill） | **4-6h** | 客户数据简单, 只需知识问答演示 |
| **标准 POC**（完整 Pipeline） | **1-2 天** | 需要多 Agent 协作 + 数据注入 |
| **深度 POC**（多 Agent + 定制） | **3-5 天** | 客户需要深度定制 Skill |

## 2. 标准化流程

### 阶段 0：行前准备（出发前 1h）

| 操作 | 工具 | 耗时 |
|------|------|:--:|
| 打包离线部署包 | FDE Dashboard → Tab 2 部署管理 → 点击"打包" | 5min |
| 确认客户行业 | 查看客户 CRM 记录 | 5min |
| **生成交付手册草稿** | FDE Dashboard → Tab 8 验证验收 → 填写行业 + 已知信息 → 点击"生成交付手册" → 下载草稿 | 3min |
| 下载对应行业 POC 模板 | `~/.aiplat/profiles/poc-{industry}.yaml` | 1min |
| 准备 USB/硬盘拷贝离线包 | `aiplat-offline-*.tar.gz` 复制到移动存储 | 10min |

> **交付手册草稿**：出发前仅有行业 + 项目名信息，生成的草稿中未知字段以 `{{待Phase X…}}` 占位。草稿是后续实施的 check list——每完成一个阶段回 Tab 8 更新一次，项目做完时手册自然填满，不用 Phase 4 突击补文档。

### 阶段 1：现场诊断（到现场后 2h）

| 操作 | 工具 | 产出 |
|------|------|------|
| 与客户方关键人开会 | 了解痛点、数据源、现有系统 | 会议纪要 |
| 填写诊断表单 | FDE Dashboard → Tab 3 客户诊断 | 诊断报告（含 Top 3 机会） |

**诊断表单字段填写指南：**

| 字段 | 填写要点 | 示例 |
|------|---------|------|
| 企业名称 | 客户完整注册名 | XX科技有限公司 |
| 行业 | 从预设清单选择；不在清单则选"其他"并在下方补填 | 金融 / 制造 / 零售 / 医疗 / 政务 / 教育 / 科技 / 其他 |
| 自定义行业 | 仅当行业选了"其他"或需细分时填写 | 新能源、物流 |
| 团队规模 | 与 AI 落地相关的技术+业务人数 | 50 |
| 痛点 | 客户核心业务痛点，逗号分隔；越具体报告越精准 | 客服效率低、数据孤岛、合规成本高 |
| 现有技术栈 | 客户已有的技术基础，逗号分隔 | Python, PostgreSQL, Kubernetes, Kafka |
| 数据源 | 客户现有数据存储/产生来源，逗号分隔 | MySQL, 日志文件, REST API, 文件服务器 |
| 合规要求 | 客户需满足的法规要求，逗号分隔 | 等保三级, GDPR, 数据不出境 |
| 预算范围 | AI 落地预期预算，可含分阶段说明 | 50-100万/年 或 一期200万 |
| 时间线 | 客户预期的时间安排 | 3个月完成POC, 6个月上线 |

> **技巧**：填写越详细诊断越精准。不确定的字段可先空着，提交后可补充信息再次提交覆盖报告。
> **📋 更新交付手册**：诊断报告出炉后，回到 Tab 8 将诊断结论填入交付手册 §1.2（客户诊断），更新项目名、行业、痛点、数据源等字段后重新生成。`agent_name` 会从这些信息自动推断。

### 阶段 2：快速部署（30min）

| 操作 | 命令/工具 |
|------|------|
| 解包 | `tar -xzf aiplat-offline-*.tar.gz` |
| 安装 | `cd aiplat-offline && ./install.sh` |
| 加载行业 POC Profile | FDE Dashboard → Tab 6 POC 工具箱 → 点击对应行业按钮 |
| 验证 | `curl localhost:8002/api/core/health` |

> **📋 更新交付手册**：部署完成后，在交付手册 §1.1 中记录部署环境信息（IP、端口、离线/在线模式）。

### 阶段 3：数据注入（1-3h）

| 操作 | 工具 | 说明 |
|------|------|------|
| 收集客户数据文件 | 向客户要 Excel/CSV/PDF/TXT | 至少 3-5 个文件 |
| 批量注入 | FDE Dashboard → Tab 6 → 选择文件 → 点击"执行数据注入" | 后台调 `poc_data_inject` Skill |
| 验证注入结果 | 查看进度条 → 确认 records > 0 | 注入失败的文件在 errors 中显示 |
| 快速检索验证 | MaterialsChat 或 Agent 对话中问"我们X数据如何？" | AI 应引用注入的数据 |

> **📋 更新交付手册**：数据注入成功后，在交付手册 §1.3 中更新样例数据数量和验证结果。如有注入失败的格式在 §5 FAQ 中记录。

### 阶段 4：POC 搭建（2-4h）

| 操作 | 工具 |
|------|------|
| 打开 Agent 管理 | 管理端 → Core → Agent 管理 |
| 选择 POC Profile | 查看 `poc-{industry}` 下预设的 Agent |
| 用 AI 自动填充配置 | 在 Agent 编辑页 → 输入角色描述 → AI 自动生成 AGENT.md |
| 可视化装配 Pipeline | WorkflowCanvas → 拖拽节点 → 连接 Agent → 保存 |
| 测试 Pipeline | 运行 Pipeline → 确认产出 |

> **📋 更新交付手册**：Agent 创建后回 Tab 8 勾选"Agent 创建指南"重新生成（自动填入 Agent 名称/模型/温度）。Workflow 搭建后勾选"Workflow 创建指南"重新生成。在交付手册 §2 中更新定制化内容和 KPI 建议。

### 阶段 5：现场 Demo（1h）

| 步骤 | 话术/操作 |
|:--:|------|
| 1. 介绍 aiPlat | "这是 aiPlat, 一个能自己进化+上前线的 AI 平台" |
| 2. 演示知识问答 | 用客户自己的数据问一个问题 |
| 3. 演示 Pipeline | 跑一遍完整 Agent 流程 |
| 4. 让客户上手 | 让客户自己问一个问题 |
| 5. 总结 | "今天用了您的真实数据, 您看哪些场景我们继续深入?" |

> **📋 更新交付手册**：Demo 结束后在交付手册 §1.4 补充实际演示内容和客户反馈。更新 §5 FAQ 中现场发现的新问题。

### 阶段 6：收尾（30min）

| 操作 | 工具 |
|------|------|
| 提交现场反馈 | FDE Dashboard → Tab 5 现场反馈 → 填写问题/环境/方案 |
| 记录客户意向 | 在反馈中标注客户优先级 |
| 同步到总部 | 联网后运行 `sync-field-feedback.sh` 或自动同步 |

## 3. 各阶段交付物

> FDE 每个阶段完成后，须确认以下交付物已产出。交付物既是自己的 check point，也是向客户汇报的材料。

| 阶段 | 交付物 | 产出方式 |
|------|--------|:---:|
| 0 — 行前准备 | 离线部署包 `.tar.gz` | Tab 2 → 打包 |
| | Agent 状态为 `ready` | 应用能力层 → Agent 库 |
| | 行业 POC 模板已加载 | Tab 6 → POC 工具箱 |
| | **交付手册草稿** (`.md`) | Tab 8 → 生成交付手册 |
| | 脱敏样例数据 3-5 份 | 客户提供 / 模拟生成 |
| 1 — 现场诊断 | **诊断报告**（含 Top 3 机会 + 部署路线图） | Tab 3 → 提交诊断 |
| | 现场反馈记录 | Tab 5 → 提交反馈 |
| 2 — 快速部署 | 服务正常运行（`curl localhost:8002/api/core/health`） | Tab 2 → 安装脚本 |
| 3 — 数据注入 | 客户数据注入成功（`records > 0`） | Tab 6 → 执行数据注入 |
| 4 — POC 搭建 | Agent 配置就绪（定制后的 AGENT.md） | Agent 管理 → 编辑 |
| | Workflow 执行一次完整流程 | Workflow 库 → 运行 |
| | POC Demo 演示完成，客户认可 | 现场演示 |
| 5 — 收尾 | 客户意向记录（优先级标记） | Tab 5 → 反馈 |

> **注意**：以上为 POC 阶段的交付物。完整项目的灰度发布(Phase 3)、验收移交(Phase 4)交付物参见 `fde-delivery-manual.md` §3-§4（验收报告、培训手册、SLA Runbook 等）。

## 4. 关键验收清单

- [ ] 客户真实数据注入成功（`records > 0`）
- [ ] AI 回答引用了客户数据（非通用知识）
- [ ] Agent Pipeline 成功执行一次完整流程
- [ ] 客户现场提了一个问题, AI 即时回答
- [ ] 现场反馈已提交

## 5. 常见问题处理

| 问题 | 解决方案 |
|------|------|
| 客户数据文件过大 (>50MB Excel) | handler.py 自动截断 max_rows=500, 不影响 Demo 效果 |
| 客户环境无网络 | 离线包已自带依赖, 无需网络 |
| OCR 解析慢 (>30s/页) | 先注入 CSV/TXT 文件做快速 Demo, PDF OCR 后台跑 |
| Agent 回答不准确 | 检查 POC Profile 是否正确加载 → 重新注入数据 → 调整 Agent prompt |
