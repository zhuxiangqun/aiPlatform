# 管理端操作手册 (L1 概要级)

本文档覆盖 aiPlat 管理端所有侧边栏页面，每个页面包含功能概述与入口位置，供数字人助手"小朱"检索并向用户解释页面功能。

## 🤖 数字人助手"小朱"（全局悬浮，所有页面可用）

- **入口**：右下角悬浮圆球。点击激活后可语音或文字提问；支持唤醒词"小朱"（浏览器语音识别）。
- **回答依据**（按来源优先级）：
  1. **当前页面实时数据**（2026-08-21 起）：已接入 8 个页面自动上报状态——诊断概览（各层健康/异常层/守卫结果）、告警中心（firing 告警数）、治理仪表盘（健康分/待审批/机制状态）、Agent 管理（运行中/异常数）、模型管理（启用/不可用数）、可观测性（活动 run/主要错误）、运行记录（run 状态/事件统计）、本体编辑器（域数/类数）。可回答"当前系统健康吗""有几个告警在触发""治理健康分多少"等状态类问题。
  2. **当前页面操作说明**：按页面标签检索 Wiki 操作手册段落，回答"这个页面怎么用"。
  3. **system_docs 知识库**：CRAG 4 级检索（GraphRAG 真向量→本体→FTS5→HyDE），回答系统功能/文档问题。
  4. **对话记忆**：同一会话内记住前几轮（session 隔离，多用户互不干扰）。
- **安全与治理**（2026-08-21 起）：后端配置 `AIPLAT_VOICE_WS_TOKEN` 后 WebSocket 握手需令牌；生产部署可用 `VITE_WS_URL` 指定语音服务地址；对话轨迹自动聚合为训练数据集（`~/.aiplat/training/sft_digital_human_*.jsonl`）。
- **数据上报接入**：新页面如需被数字人感知，在组件内调用 `reportPageData(route, data)`（前端 `lib/pageDataBridge.ts`），卸载时 `clearPageData(route)`。

## 📊 仪表盘

### 系统概览
- **路由**: `/system-overview`
- **功能**: 展示整个 AI 平台的运行概况，包括 Agent 数量、Skill 数量、模型健康状态、最近的流水线执行统计等关键指标。作为平台首页，提供一站式状态总览。

### 告警中心
- **路由**: `/alerts`
- **功能**: 集中展示系统告警信息，包括模型调用异常、流水线失败、审批超时、安全事件等。支持按级别（严重/警告/信息）过滤和告警确认/处理操作。

### 系统图谱
- **路由**: `/system-graph`
- **功能**: 以可视化图谱方式展示平台各组件之间的依赖关系，包括 Agent→Skill→Tool 依赖链、模型调用链路、服务间通信拓扑等。

### 治理仪表盘
- **路由**: `/governance`
- **功能**: 展示平台治理相关的度量指标，包括审计合规率、安全扫描结果、策略执行情况、架构守卫检测结果等。用于治理层面的决策支持。

### 价值看板
- **路由**: `/value-center`
- **功能**: 展示 AI 应用落地的业务价值度量，包括项目收益、成本节省、效率提升等 ROI 指标。帮助管理者了解 AI 投资的回报情况。

## 🧠 知识工厂

### 数据源
#### Vault 文档库
- **路由**: `/platform/kb/vault`
- **功能**: 管理文档存储库，支持上传 PDF、DOCX、PPTX、HTML、Markdown 等多种格式文档。文档上传后自动进入解析→分块→索引→入图管线。

### 本体模型
#### 本体编辑器
- **路由**: `/ontology-editor`
- **功能**: 可视化编辑领域本体（Ontology），支持创建/修改类定义、属性关系、状态机、推理规则。是构建领域知识模型的入口。
- **操作指南**:
  - **选择域**：顶部下拉选择要编辑的域本体（如 AI知识、船舶设计等）。切换域后自动加载该域的所有类定义。
  - **创建类**：点击"添加类"，填写类名、标签、描述、必填字段、可选字段、分类标签。每个字段可定义类型（string/enum/number）和枚举值列表。
  - **编辑属性**：选择类后在属性面板中编辑字段列表、状态机、转换规则。状态转换规则必须满足唯一性、覆盖完整性和侧效应显式声明。
  - **推理规则**：在推理规则面板中定义 premises→conclusion 规则，支持 2-4 条前提，置信度自动乘以折扣因子。
  - **保存与生效**：修改后点击"保存"，引擎自动失效缓存并重建索引。下次 Agent 执行时加载新本体。

#### 域本体管理
- **路由**: `/infra/ontology`
- **功能**: 管理已注册的领域本体列表，包括 AI 知识、船舶设计、供应链、采购等域。支持创建新域、导入 YAML 本体定义、查看域健康状态。

### 知识库
#### 向量知识库
- **路由**: `/platform/kb`
- **功能**: 管理向量化的知识文档，文档经分块和嵌入后存储为向量索引。支持按域过滤、查看文档详情、检查文档质量评分和过期状态。
- **操作指南**:
  - **上传文档**：点击"上传"按钮，支持 PDF/DOCX/PPTX/HTML/MD 等格式。上传后自动进入解析→分块→嵌入→入图管线。
  - **文档管理**：列表显示所有已入库文档，每行显示文档名、状态（处理中/已完成/失败）、上传时间、所属域。支持单个删除或批量操作。
  - **检索测试**：内置检索测试面板，输入查询语句后展示 Top-K 召回结果，包括来源文档、分数、检索路径（本体优先/FTS5/HyDE）。

#### LLM Wiki
- **路由**: `/platform/kb/wiki`
- **功能**: 浏览和管理 LLM 可访问的 Wiki 页面。Wiki 页面由知识合成引擎自动生成，也可手动创建和编辑。每个页面包含结构化 frontmatter 和语义标记。
- **操作指南**:
  - **浏览页面**：左侧目录树按分类组织，点击展开子类目。主区域显示选中页面的完整 Markdown 内容。
  - **创建页面**：点击"新建"，填写标题、分类、标签、正文。正文支持 Markdown 格式，frontmatter 自动生成。
  - **编辑页面**：在页面详情中点击"编辑"，修改后保存。引擎会自动更新向量缓存和推理缓存。
  - **页面关系**：每个页面底部显示关联页面、来源文章、矛盾声明（如有）。系统自动检测内容冲突并标记。
  - **版本历史**：每个页面有完整的版本记录，支持查看历史版本和对比差异。

### 质量验证
#### 检索评估
- **路由**: `/platform/kb/eval`
- **功能**: 评估 RAG 检索质量，包括 Recall@10、Precision、MRR 等指标。支持运行评估测试集（Golden Queries），查看检索策略效果对比。

#### 质量反馈
- **路由**: `/platform/kb/health`
- **功能**: 展示知识库健康状态，包括文档覆盖率、过期文档数、孤立实体数、质量信号趋势等。支持查看和响应自动生成的质量告警。

## 🤖 AI 应用工厂

### 应用工厂（AI App Factory）
- **路由**: `/app/factory`（全局唯一入口，替代旧 `/studio` 与 `/app/builder` 的项目创建）
- **功能**: 把"一句话业务需求"变成"已部署的 AI 应用"的自动化产线。三种模式（顶部 Tab 切换，记忆上次选择）：
  - **快速开始**（默认）：选能力（来自 workbench capabilities）→ 填描述 → 一键启动，跟踪 run 进度。
  - **对话式**：和 AI 聊天澄清需求（PM agent + 知识库检索增强），自动组队执行。
  - **高级配置**：项目列表 + 全生命周期详情（PRD 编辑/阶段产物/HITL 审批/修复回滚/部署预览）。
- **生命周期**（后端 `builder_project_service.py`，40+ 端点）：对话澄清需求 → PRD 生成与确认（`confirm`）→ 自动组队（`recommend-team`，AI 推断 + Agent 历史性能表）→ 流水线执行（core PipelineEngine：架构→代码→测试）→ HITL 审批（`approve/reject`）→ 失败自动修复（`fix`/`regenerate`）→ 回滚（`rollback/{stage}`/`rollback-prd`）→ 部署（`deploy`，按测试通过率计算 pass_rate）→ 已部署应用预览（`/app/apps`）。
- **双模式自动路由**（核心机制，`team_planner.py:471-476`）：规划 Agent 分析 PRD 后**先输出 `mode` 字段**自动判断采用哪套处理：
  - **`agent` 模式**（→ `~/.aiplat/teams/default.yaml`）：需求核心是**自然语言交互/对话/多轮问答**（聊天机器人、问答助手）。产出 **AGENT.md + SKILL.md 配置 + app_page.json 页面协议**——"AI 应用"路线，不生成原生代码，由平台预置组件动态渲染。
  - **`code` 模式**（→ `~/.aiplat/teams/code.yaml`）：需求核心是**确定性计算/API/CRUD/性能敏感**（上传转码、数据分析、表单）。产出**真实源代码**（`programmer_agent` → `code_generation`，`uses_file_output` + `deploy_files_to_disk` 落盘）+ 真 pytest 测试。
  - 判断标准："核心是自然语言交互还是确定性计算/API？只有这两种，不输出 hybrid"。
- **pass_rate 来源标注**（2026-08-22 起）：运行记录里的 `pass_rate` 带 `pass_rate_source` 字段——`real_pytest`（真实测试通过率，可信）或 `estimated`（无真实测试时按产物完整度估算，仅作参考，附 `pass_rate_estimate_reason`）。
- **双入口说明**：`/app/factory`（AIFactory，3 模式容器）与 `/app/builder/projects`（ProjectsPage，纯列表 255 行）共用同一后端 `/platform/builder/projects`——factory 是完整入口，builder/projects 是精简列表视图。
- **数字人感知**（2026-08-22 起）：应用工厂页已接入 `reportPageData('/app/factory', ...)`——数字人可回答"有几个项目在跑？""平均通过率多少？""当前选中项目什么阶段？"。
- **导入既有代码（L2，2026-08-22 起）**：项目详情页新增"📥 导入既有代码（L2）"面板，用于改造老项目。操作流程：
  1. 点击"导入 / 管理"→ **首次弹出《预期管理手册》**（必须点"同意以上规则"才能继续，核心认知：L2 会把勾选的文件**整体重写**而非增量合并——"熔铁重铸，不是焊把手"）。
  2. **导入**：上传 zip 或填 AIPLAT_HOME 内路径（如 `~/.aiplat/legacy_app`）。导入后展示文件清单（含大小/语言），并自动检测 `tests/` 目录与依赖文件。
  3. **勾选 + 填意图**：勾选要改的文件，**每个文件必须填一句"修改意图"**（如"登录增加验证码校验"）——空意图不能提交，AI 不猜路径。列表顶部有红字警告："当前版本将根据旧代码【重写】该文件，而非合并改动，请确认已备份"。
  4. **无测试兜底**：若项目没有 `tests/` 目录，会出现"跳过测试门禁"开关——开启后代码即使跑不通测试也能部署（通过率为**估算值**，非实测）。涉及登录/支付/权限类变更会二次确认。
  5. **重建**：点"保存修改意图并重建"→ 流水线用"行为契约"重写勾选文件（保留对外接口：函数名/类名/路由路径），不碰未勾选文件。
  6. **部署后提醒**：运行记录/部署区刷屏显示 `Warning: File xxx has been regenerated, please review diff manually.`——L2 没有 Diff 视图，**必须人工 Review 被重写文件**。
  - **后悔药**：不满意 → 点"回滚 PRD"→ 到 `~/.aiplat/apps/{项目}/imported/` 找回原件 → 重新勾选重写。
  - **期望管理**：改出来的代码是"AI 风格 + 你原来的接口名"；生僻写法（元类/装饰器嵌套/猴子补丁）大概率被标准写法替换。追求逐行可控请等 L3（增量合并引擎）。

#### FDE 工作台
- **路由**: `/diagnostics/fde`
- **功能**: **前线诊断与交付工作台**，是 FDE 工程师的主操作界面。支持两种模式：
  - **自由模式（默认）**: 按 8 个步骤流程操作：客户→域→诊断→POC→部署→灰度→验收→监控
  - **向导模式**: 填写企业信息后 AI 自动生成诊断报告（含 Top 3 落地机会、部署路线图、风险清单）
  底部有域健康面板和本体编辑器入口，支持 12+ 行业域。
- **操作指南**:
  - **自由模式**：页面顶部显示 8 步进度条（①→⑧），点击步骤标签切换面板。第①步选择或创建客户 Profile；第②步选择业务域；第③步运行诊断；后续步骤按诊断结果逐步推进。每个步骤完成后自动标记为✅。
  - **向导模式**：右上角下拉切换为"向导模式"。填写企业名称（选填）、选择行业（必填）、自定义行业（选填）、团队规模（选填）、痛点描述（必填*）。点击"提交诊断"后 AI 生成结构化分析报告。
  - **客户 Profile 管理**：第①步"业务认知"面板中可新建/编辑/删除客户 Profile。新建时填写客户名称、行业、描述等信息，支持 AI 辅助生成。
  - **域健康面板**：底部折叠面板显示已注册业务域的健康评分（0-100分），颜色药丸标识等级（绿/黄/红）。点击可展开查看该域的实体数、关系数、Wiki页面数等详情。
  - **本体编辑器入口**：底部有个"📝 本体编辑器"按钮，点击跳转到域本体的可视化编辑界面，可创建/修改类定义、属性、状态机。
  - **小朱助手**：右下角悬浮圆球，点击唤醒后可语音/文字提问。会基于当前页面上下文回答功能问题。
  - **常见问题**：
    - *客户 Profile 不显示* → 检查平台服务是否启动（端口8003），接口路径是否正确。
    - *诊断报告为空* → 确认已选择行业并填写痛点描述，必填项不可留空。
    - *进度条不动* → 自由模式下需手动完成每个步骤才会前进；向导模式提交后自动流转。

#### 我的项目
- **路由**: `/app/builder`
- **功能**: 管理个人创建或参与的 Builder 项目。每个项目包含可配置的流水线阶段（PM→Architect→Programmer→QA），支持 HITL 审批和状态跟踪。
- **操作指南**:
  - **项目列表**：卡片式布局展示所有项目，每张卡片显示项目名称、描述、团队角色数、最新运行状态（通过率/时间/token消耗）。
  - **进入项目**：点击卡片进入项目详情页，可查看流水线状态、阶段输出产物、运行历史。
  - **删除项目**：每张卡片右上角有删除按钮，点击后确认即可删除。支持多选批量删除：勾选卡片前的复选框→选中多个→点击"删除选中"。
  - **清理空项目**：工具栏有"清理0%通过率"按钮，一键删除所有从未成功运行的项目。
  - **创建项目**：点击"新建项目"，用自然语言描述需求，AI PM 将对话澄清后自动生成 PRD。系统会避免创建同名同描述的重复项目（返回已有项目而非新建）。

#### 已部署应用
- **路由**: `/app/apps`
- **功能**: 查看和管理已部署上线的 AI 应用，包括应用运行状态、访问端点、版本信息、配置历史等。

### 能力组装
#### Agent 管理
- **路由**: `/core/agents`
- **功能**: 管理所有 Agent 配置，包括引擎内置 Agent 和用户工作区 Agent。支持查看 Agent 类型（ReAct/Conversational/RAG/Multi-Agent 等）、绑定 Skill/Tool、编辑 AGENT.md 操作手册。
- **操作指南**:
  - **查看 Agent 详情**：列表页显示所有已注册 Agent，点击进入详情页可查看 Agent 类型、绑定的 Skill 列表、Tool 权限、AGENT.md 完整内容。
  - **创建 Agent**：点击"新建 Agent"，填写名称、选择类型（ReAct/RAG/Conversational 等）、绑定 Skill 和 Tool、编写 AGENT.md 操作手册（SOP 步骤 + 输出格式 + 反模式）。
  - **编辑 AGENT.md**：在详情页可直接编辑 AGENT.md 的 Markdown 内容。AGENT.md 应遵循三层分离原则：人格（SOUL.md）、操作规则（SOP）、长期记忆（MEMORY.md）。保存后立即生效，下次 Agent 执行时加载。
  - **启用/禁用**：切换开关控制 Agent 是否参与执行。禁用的 Agent 不会出现在流水线阶段的可选 Agent 列表中。
  - **常见问题**：
    - *Agent 列表为空* → 检查 Engine Skills 是否已加载（`~/.aiplat/agents/` 目录下有 AGENT.md 文件）。
    - *AGENT.md 修改不生效* → 重启服务或等待 Agent 下次执行时自动重载。

#### Skill 管理
- **路由**: `/core/skills`
- **功能**: 管理所有 Skill 的注册和配置。Skill 是 Agent 可调用的可复用能力单元，分为引擎内置和用户工作区两类。支持查看执行类型（handler/prompt）、输入输出 schema、副作用声明。
- **操作指南**:
  - **查看 Skill**：列表显示名称、执行类型（handler 有真实代码 / prompt 纯 LLM）、输入输出 schema、副作用类型（read/write/execute）。
  - **测试 Skill**：点击"执行"按钮，输入 JSON 参数后提交，查看返回结果和执行耗时。
  - **创建 Skill**：点击"新建"，编写 SKILL.md（包含 frontmatter 声明 name/version/execution_type + SOP 正文）。execution_type 为 handler 时需同时创建 handler.py。
  - **注意事项**：确保 execution_type 声明与实际实现一致，否则执行时会记录 WARNING 审计事件。副作用声明必须准确，引擎会据此判断重试安全性。

#### Workflow 管理
- **路由**: `/core/workflows`
- **功能**: 管理流水线工作流配置。定义 Agent 编排顺序、HITL 暂停点、失败策略（跳过/回退/fallback）等。
- **操作指南**:
  - **查看 Workflow**：列表展示所有已定义的工作流，点击进入可查看阶段编排图（节点→边）、每个阶段的 Agent 配置和参数。
  - **创建 Workflow**：点击"新建"，通过可视化编辑器拖拽 Agent 节点并连线，配置每个阶段的 prompt_extra、failure_strategy、hitl 等参数。
  - **执行模式**：支持链式（顺序执行）、路由（按条件分发）、并行（多节点同时）、编排（动态子任务）。选择时优先从简单模式开始。
  - **HITL 配置**：在需要人工审批的阶段设置 hitl=true，流水线将在该阶段暂停等待审批。审批通过后继续执行，拒绝则按 failure_strategy 处理。

#### Tool 管理
- **路由**: `/core/tools`
- **功能**: 管理 Agent 可用的工具集，包括文件读写、代码执行、数据库查询、网页浏览等。每个 Tool 有独立的权限声明和资源范围配置。

#### MCP 连接
- **路由**: `/core/mcp`
- **功能**: 管理 Model Context Protocol（MCP）服务器的连接配置。MCP 允许接入外部工具服务，所有 MCP Tool 通过标准 syscall→PolicyGate 路径执行，与本地 Tool 权限一视同仁。
- **操作指南**:
  - **连接管理**：列表显示所有已注册 MCP 服务器，包括名称、连接状态、工具数量。支持添��/删除/重连操作。
  - **添加 MCP Server**：点击"添加"，填写 server.yaml 配置（传输方式 SSE/Stdio、端点 URL、认证信息）。配置后系统自动连接并注册所有暴露的 Tool。
  - **工具权限**：MCP 导入的 Tool 与本地 Tool 权限一致，均经过 PolicyGate + ApprovalGate 双门禁。可在 Tool 管理页面单独调整权限。
  - **注意事项**：避免接入过多 MCP Server（推荐 ≤5 个），每个 MCP 的工具描述可能占据 1000-2000 token 上下文空间。

#### Memory 管理
- **路由**: `/core/memory`
- **功能**: 管理 Agent 的记忆系统。查看四层记忆状态（Working/Episodic/Semantic/Task Skills），包括压缩策略、过期清理、投毒防御配置。

#### 能力市场
- **路由**: `/workspace/marketplace`
- **功能**: 浏览和安装社区/团队共享的 Agent、Skill、Tool 模板。支持评分、评论和一键安装到工作区。

### 运行时配置
#### 提示词配置
- **路由**: `/core/prompts`
- **功能**: 管理 LLM 调用的提示词模板。支持注册、版本化（`id@version`）、变量占位符、按域定制。所有业务提示词通过此入口管理，禁止在代码中硬编码。

#### 变量管理
- **路由**: `/core/variables`
- **功能**: 管理全局变量和环境变量配置，包括 Pipeline 阶段参数、Agent 行为开关（如 token 预算、温度参数）、外部服务端点等。

#### 凭证管理
- **路由**: `/core/credentials`
- **功能**: 安全管理 API Key、数据库密码、外部服务 Token 等敏感凭证。凭证加密存储，运行时通过 secrets 模块安全注入，日志自动脱敏。

## 🩺 诊断与治理

### 平台健康
#### 诊断概览
- **路由**: `/diagnostics`
- **功能**: **诊断中心主页面**，集中展示平台各项健康检查结果。覆盖 27+ 项检查维度，包括核心运行时、数据层、模型服务、安全合规等，每项标注通过/警告/失败状态。
- **操作指南**:
  - **运行诊断**：点击"运行全量诊断"，系统并行执行所有 27+ 项检查，数秒内返回结果。每项检查显示名称、状态图标（✅/⚠️/❌）、耗时、详情描述。
  - **分类查看**：诊断项按类别分组（核心运行时/数据层/模型服务/安全合规等），可折叠/展开查看。
  - **历史对比**：页面顶部有时间线，可查看历史诊断运行记录，对比不同时间点的健康趋势变化。
  - **LLM 审查**：诊断结果中包含 Autoreview 审查记录，点击可查看代码审查详情和 clean 率趋势。
  - **修复建议**：对于 ❌ 失败项，点击展开可查看详细错误信息和自动生成的修复建议。

#### 控制画像
- **路由**: `/diagnostics/control-profile`
- **功能**: 展示和编辑控制画像（Control Profile），定义 Agent 运行时的行为约束，包括工具白名单、上下文层启用/禁用、token 预算限制等。

#### 可观测性
- **路由**: `/diagnostics/observability`
- **功能**: 实时监控系统运行指标，包括 trace/span 追踪、LLM 调用延迟、token 消耗统计、错误率趋势等。所有关键路径决策在此可追溯。
- **操作指南**:
  - **Trace 追踪**：每个请求生成唯一 trace_id，可在追踪面板中按 trace_id 搜索，查看完整调用链（Agent→Skill→LLM→Tool）。
  - **延迟分析**：图表展示 P50/P95/P99 延迟分布，可按模型、操作类型、时间段过滤。
  - **Token 消耗**：按 Agent/项目/时间段统计 token 消耗量，支持预算预警设置。
  - **错误监控**：错误率趋势图 + 错误类型分布（超时/格式错误/权限拒绝/限流等）。

### 知识健康
#### 本体审计
- **路由**: `/diagnostics/knowledge-health`
- **功能**: 审计领域本体的健康状态，包括类覆盖率、属性完整性、推理规则有效性、状态机覆盖率等。发现缺失或异常自动生成修复建议。

#### 知识漂移
- **路由**: `/diagnostics/drift-status`
- **功能**: 监测知识库数据漂移状态，当文档更新导致旧有推理结论不一致时告警。支持查看漂移详情和触发重新合成。

#### LLM 审查
- **路由**: `/diagnostics/llm-review`
- **功能**: 对 LLM 输出进行质量审查，包括 Autoreview Skill 的审查结果历史、幻觉检测报告、clean 率趋势和人工否决记录。

### 项目健康
#### 业务价值
- **路由**: `/diagnostics/business-value`
- **功能**: 评估 AI 项目的业务价值达成情况，对比预期与实际的 ROI、使用率、用户满意度等指标。

#### Agent 评估
- **路由**: `/diagnostics/eval`
- **功能**: 对 Agent 进行自动化评估，包括任务完成率、响应准确率、工具调用成功率等。支持运行预设评估用例和查看历史评估趋势。

#### 修复中心
- **路由**: `/diagnostics/repairs`
- **功能**: 集中展示和管理自动修复建议（P0/P1/P2 级别），包括架构违规、安全漏洞、性能问题等。支持一键执行修复或手动标记处理。

### 安全与合规
#### 安全监控
- **路由**: `/diagnostics/safety`
- **功能**: 实时监控平台安全事件，包括提示词注入检测、PII 泄露告警、异常访问行为、密钥暴露风险等。所有安全事件自动记录审计日志。

#### 审计日志
- **路由**: `/diagnostics/audit`
- **功能**: 浏览和检索平台所有操作审计记录，包括用户登录、Agent 执行、Tool 调用、配置变更、权限操作等。支持按时间、用户、操作类型过滤和导出。
- **操作指南**:
  - **日志搜索**：顶部搜索栏支持模糊搜索和高级过滤（按时间范围、用户、操作类型、结果状态）。支持实时刷新。
  - **导出功能**：可将过滤后的审计日志导出为 CSV/JSON 格式，用于外部审计或合规报告。
  - **安全事件**：安全相关事件（注入检测、PII 泄露、权限异常）会高亮标记，支持配置告警通知。

#### 变更控制
- **路由**: `/diagnostics/change-control`
- **功能**: 管理平台配置和代码的变更审批流程。每次变更需经过架构守卫检查后方可合入，确保核心层（harness/infra）改动不会引入回归。

### 审批管理
#### 资产审批
- **路由**: `/approval`
- **功能**: 管理知识资产的上线/下线审批，包括 Wiki 页面发布、本体定义变更、文档入库等。审批通过后资产自动同步到生产索引。
- **操作指南**:
  - **审批列表**：卡片式展示所有待审批/已审批项，每项显示资产名称、申请人、申请时间、状态（待审批/已通过/已拒绝）。
  - **审批操作**：点击进入详情，查看变更内容对比（如 Wiki 页面前后差异），选择通过或拒绝并填写审批意见。审批记录自动归档。
  - **审批记录**：在"审批记录"页面可按时间/状态/申请人过滤查看历史审批，支持导出审计报告。

#### 运行时审批
- **路由**: `/core/approvals`
- **功能**: 管理 Agent 运行时的操作审批，包括 Agent 创建/删除、Skill 注册/更新、Tool 权限变更等。PolicyGate 在此执行权限检查。

#### 审批记录
- **路由**: `/approval/history`
- **功能**: 查看所有审批的历史记录，包括审批人、时间、决策、备注等。支持按状态（待审批/已通过/已拒绝）过滤。

## ⚙️ 平台设置

### 日常运维
#### 模型管理
- **路由**: `/infra/models`
- **功能**: 管理平台可用的 AI 模型列表，包括远程 API 模型（DeepSeek/Qwen/OpenAI 等）和本地模型（Ollama/LM Studio）。显示模型健康状态、启用/禁用控制、能力标签。
- **操作指南**:
  - **模型列表**：表格展示所有已发现模型，每列显示模型名、所属 provider、能力标签（chat/code_gen/embedding）、启用状态、健康检查结果。
  - **启用/禁用**：切换开关控制模型是否参与路由。禁用的模型不会出现在 `best_model_for_purpose()` 的候选列表中。
  - **健康检查**：系统自动定期 ping 模型接口，标记不可达模型。手动点击"检查"按钮可即时刷新健康状态。
  - **新增模型**：环境变量方式配置（如 `AIPLAT_LLM_MODEL=deepseek-v4-pro`），系统启动时自动发现并注册。OpenAI 兼容的 provider 走统一适配器，无需新增代码。
  - **注意事项**：模型管理以 infra ModelManager 为唯一真相源，core 不自行维护模型列表。模型解析也通过统一入口，不可各模块独立读取环境变量。

#### 模型微调
- **路由**: `/infra/finetune`
- **功能**: 管理模型的微调任务，包括 LoRA 微调配置、训练数据集上传、训练进度监控、微调后模型的版本管理和 A/B 测试。

#### 存储管理
- **路由**: `/infra/storage`
- **功能**: 管理平台存储资源，包括向量数据库状态、文档存储使用量、数据库连接配置、缓存清理等。

#### 算力调度
- **路由**: `/infra/scheduler`
- **功能**: 管理 GPU 计算资源的调度策略，包括任务优先级配置、并发限制、资源分配规则、排队状态监控。

### 平台配置
#### API 网关
- **路由**: `/platform/gateway`

#### 认证鉴权

#### 多租户管理

- **功能**: 管理多租户配置，包括创建/删除租户、设置租户隔离策略（数据/模型/Agent 隔离）、租户配额管理。

#### 渠道管理
- **路由**: `/app/channels`

### 系统运维
