## 幻灯片结构（建议 25 分钟讲 + 20 分钟拍板）

### 第 1 页 · 标题

**标题**：aiPlat 五产品域 — 方向与首切片批准请求  
**副标题**：产品边界独立 · 接口可组合 · 部署按需拆分  
**页脚**：有条件批 L1（WP0–WP2）；不批切片执行 / 五服务拆分 / 全仓搬迁

---

### 第 2 页 · 为什么现在要做

| 痛点 | 后果 |
|------|------|
| Pi 被误解成「小 aiPlat」 | 交付承诺错位 |
| 本体 / RAG / Knowledge 混权 | 双权威、不可追溯 |
| FDE 直触内部能力 | 交付平台变「页面+私有调用」 |
| 诊断 ≈ Management 页 | 无法跨产品举证 |
| 静态门禁绿 =「可用」 | 伪就绪 |

**一句话**：先定产品与契约，再用一条真实路径证明边界。

---

### 第 3 页 · 五个产品（一张表）

| 产品 | 用户 | 权威数据 | 不负责 |
|------|------|----------|--------|
| aiPlat | 平台/Agent 开发 | 租户策略、Agent 资产 | 本体/FDE/诊断权威库 |
| Pi | 部署/运维 | Runtime 与执行状态 | 中心 IAM 权威 |
| 本体 | 数据治理/领域 | Ontology/Mapping/语义数据 | Agent 生命周期 |
| FDE | 交付工程师 | 项目/需求/验收证据 | 自建 Runtime/本体引擎 |
| 诊断 | SRE/质量/安全 | 评测与诊断报告 | 源系统唯一事实、默认修复权 |

**脚注**：产品独立 ≠ 立刻微服务。

---

### 第 5 页 · 本次请求批准什么

**批准（有条件 L1）**

1. **≤2 周** WP0：路径边登记 As-Is / Known Gap / Blocker  
2. WP1–WP2：启用集最小契约 + 兼容矩阵  
3. 目标路径仅**准备**；开跑另批 Gate 1

**路径**：`FDE → aiPlat Bundle → Pi → 诊断(Pi+aiPlat) → FDE 验收`（本体非必经）

**不批准**

- WP3–WP4（须独立 Gate 1）  
- 五仓库 / 五库 / 五微服务；全仓搬迁；诊断全功能  
- 无 D13 客户背书过 Gate 2；Pi Thin = Enterprise  

---

### 第 6 页 · 会上必须拍板的 5 项

| # | 决策 | 建议默认 |
|---|------|----------|
| 1 | 首切片场景 | 会前业务提名；无客户则内部场景并标「非客户验收」 |
| 2 | 业务验收人 | 能签失败标准的人 |
| 3 | Pi 形态 | Thin；或声明子集的 Enterprise |
| 4 | 控制面/IAM | aiPlat 默认；禁止双重授权 |
| 5 | Gate1/暂停签署 | 架构 owner × 业务 owner 双签 |

---

### 第 7 页 · Gate 与时间盒

```text
[L1] WP0–WP2 → [另批] Gate1 → WP3–WP4 → [另批] Gate2 → [另批] Gate3
```

| Gate | 含义 |
|------|------|
| Gate 1 | 无 Blocker；Known Gap 可带设计开工；**不要求**已有端到端 E3 |
| Gate 2 | WP4 通过 + D13 背书原件 → 扩大 |
| Gate 3 | 证据+成本；架构×业务联签 |

---

### 第 8 页 · 成功标准（分阶段）

**L1**：盘点可回溯；缺口分类正确；启用集契约可测。  
**切片完成（Gate1 后）**：无未授权跨库直写；版本可关联；不伪报成功；路径 ≥ **E3**、对外 ≥ **E4**（不降标）。

---

### 第 9 页 · 风险（三句）

1. **范围膨胀** → 只准一条切片；变更走 ADR  
2. **权限旁路** → 服务端校验；客户端 gate 不算数  
3. **伪健康** → unknown/stale 为硬验收  

暂停：架构 × 业务联合签署；单一产品 owner 不能单方面恢复。
