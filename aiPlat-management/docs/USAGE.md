## 1. 流水线构建

**入口**：侧边栏 > 应用能力层 > 团队组装

**路径**：`/workspace/teams`

### 操作步骤

1. 点击 **"新建团队"**
2. 在左侧 **角色池** 浏览 Agent，分类筛选（研发/质量/设计等）
3. 点击 Agent 旁的 **⊕** 将其加入团队画布
4. 在 **团队成员画布** 中调整：
   - **上下箭头**：调整执行顺序
   - **✓ 按钮**：开启/关闭该阶段的人工审批（HITL）
   - **下拉框**：设置失败后的回退目标
   - **叉号**：移出该 Agent
5. 点击 **条件路由 ▼** 展开配置条件跳转（见第 2 节）
6. 输入团队名称，点击 **保存**

### 启动流水线

1. 侧边栏 > 应用接入层 > 应用工作台 > 新建项目
2. 用自然语言描述需求（如"做一个用户登录系统"）
3. 选择刚才创建的团队
4. 点击 **开始构建**

## 2. 条件路由

**入口**：团队组装页 > 每个成员卡片 > 点击 **"条件路由 ▼"**

### 操作步骤

1. 点击展开，显示当前路由规则（0 条时为空）
2. 点击 **"+ 添加条件"** 新增一条规则
3. 配置规则：
   - **条件表达式**（左输入框）：如 `status=="ok"`、`result.pass_rate > 0.8`
   - **跳转目标**（右下拉框）：选择跳转到哪个 Stage
4. 点击 ✕ 删除不需要的规则

### 条件语法

| 示例 | 含义 |
|------|------|
| `status=="ok"` | 该 Stage 执行成功 |
| `status=="failed"` | 该 Stage 执行失败 |
| `result.pass_rate > 0.8` | 产出物的 pass_rate 超过 80% |
| `error is not None` | 有错误信息 |
| `error is None` | 没有错误 |
| `status=="ok" and score > 10` | 成功且分数超过 10 |

引擎在每个 Stage 执行完后按规则**从上到下匹配**，命中第一条就跳转，不命中则按正常顺序继续。

## 3. 导入/导出/模板

**入口**：团队组装页 > 保存栏

### 导出为 JSON

1. 配好团队后，点击 **导出**
2. 自动下载 `xxx_pipeline.json`

### 从 JSON 导入

1. 点击 **导入**，选择 `.json` 文件
2. 自动填充所有 Stages 和团队名称

### 保存为模板

1. 点击 **模板**
2. 输入模板名称
3. 模板自动保存到浏览器本地（最多 20 个）

### 加载模板

1. 点击 **加载▼** 打开下拉菜单
2. 点击模板名称加载（显示 `N 阶段`）
3. 点击 ✕ 可删除模板

## 4. 即时测试

**入口**：团队组装页 > 右上角 **[测试]** 按钮

### 操作步骤

1. 团队至少有一个 Agent 后，**[测试]** 按钮出现
2. 点击展开聊天面板
3. 输入测试消息（如"这个流水线适合做什么项目？"）
4. 按 Enter 发送 → AI 根据当前流水线阶段配置回复
5. 再次点击 **[关闭测试]** 收起面板

## 5. 执行可视化

### 在项目工作台

创建项目并启动流水线后，**项目详情页**自动展示执行进度：
- **DAG 拓扑图**：节点和箭头的可视化
- **阶段卡片**：每个 Stage 的状态 + 产出物预览
- 每 2 秒自动刷新

### 在 Workflow 画布

**入口**：侧边栏 > 应用能力层 > Workflow

1. 新建或打开一个 Workflow
2. 点击 **[▶ 运行]**
3. 画布顶部自动展开 **执行视图面板**，显示：
   - 进度条 + 完成计数
   - 每个节点的状态（运行中蓝点/完成绿点/失败红点）
   - Token 消耗和成本
4. **点击节点** 展开详细面板（输入参数/输出结果/错误/Token 明细）
5. 执行完成后点击 **"关闭执行视图"** 收起

## 6. 执行回放

### 方式一：从运行历史进入

1. Workflow 画布顶部工具栏 > 点击 **时钟图标** 🕐
2. 下拉菜单显示最近的运行记录（绿点=成功/红点=失败/黄点=运行中）
3. 点击某条记录 → 弹出回放面板

### 方式二：从 Run 对比进入

见第 7 节。

### 播放控制

| 按钮 | 功能 |
|------|------|
| **▶ 播放** / **⏸ 暂停** | 开始/暂停动画 |
| **↺ 重放** | 从头播放 |
| **速度选择**（0.5x/1x/2x/5x/10x） | 控制播放速度 |
| 进度条 | 显示当前位置 |

## 7. Run 对比

**入口**：诊断中心 > 工具箱 > Run 对比

**路径**：`/diagnostics/run-comparison`

### 操作步骤

1. 输入两个 **Run ID**（可从运行历史复制）
2. 点击 **对比**
3. 两个执行视窗并排，各自以回放模式展示执行过程
4. 对比两边的节点数、耗时、Token 消耗

## 8. 可观测性仪表板

**入口**：诊断中心 > 工具箱 > Observability

**路径**：`/diagnostics/observability`

### 说明

自动聚合并展示系统运行数据（每 30 秒刷新）：

| 指标 | 说明 |
|------|------|
| **LLM 调用总数** | 24h 内的 LLM 调用量和成功率 |
| **总 Token 消耗** | 输入 + 输出 Token |
| **平均延迟** | 平均/最大响应时间 |
| **活跃运行** | 最近 1 小时正在执行的流水线数量 |
| **预估成本** | 24h 累计（按 $1/M input + $3/M output 估算） |

### 图表区

- **事件吞吐量**：每 5 分钟的事件数量柱状图
- **错误率趋势**：每 30 分钟的错误占比时间线
- **Syscall 分布**：按类型（LLM/工具/技能）的调用量和平均延迟
- **模型使用分布**：各模型的调用数和 Token 消耗
- **Top 错误**：最常见的错误信息排名

### 活跃告警

红色横幅显示当前触发的阈值告警（如"错误率超过 20%"）。

### 快捷链接

从仪表板可一键跳转到：
- Syscall 事件列表
- 链路追踪
- Run 对比
- Ops/DLQ

## 9. 告警配置

**入口**：可观测性仪表板底部 > 点击 **"告警阈值配置 ▼"**

### 内置规则

| 规则 | 默认 | 说明 |
|------|------|------|
| 错误率 > 20% | ✅ 启用 | LLM 调用错误率超过 20% 时告警 |
| 平均延迟 > 5s | ❌ 未启用 | 平均响应时间超过 5 秒 |
| 成功率 < 80% | ❌ 未启用 | 总成功率低于 80% |

### 操作步骤

1. 点击展开配置面板
2. **勾选/取消勾选**：启用/禁用某条规则
3. **修改数值**：调整阈值（如把 20% 改成 10%）
4. 点击 **保存配置** 将规则持久化到 SQLite

## 10. 模型 Playground

**入口**：诊断中心 > 工具箱 > Model Playground

**路径**：`/diagnostics/model-playground`

### 操作步骤

1. 输入 **Prompt**（如"写一个快速排序的 Python 实现"）
2. 点击 **选择模型 (0/6)**，从下拉列表勾选要对比的模型
3. 已选模型以彩色标签显示，点击 ✕ 移除
4. 点击 **▶ 运行对比**
5. 结果并排显示：
   - 模型名称 + 响应时间 + Token 消耗
   - 每个模型的完整输出
   - 点击 📋 复制单个模型的输出

### 限制

- 最多同时对比 **6 个** 模型
- 模型列表来自 infra 层自动发现的可用 LLM

## 11. 系统变量参考（Workflow 画布）

在 Workflow 画布的节点配置中可引用以下系统变量（使用 `{{变量名}}` 语法）：

| 变量名 | 说明 |
|--------|------|
| `{{sys.query}}` | 用户输入 |
| `{{sys.user_id}}` | 当前用户 ID |
| `{{sys.app_id}}` | 当前应用 ID |
| `{{sys.session_id}}` | 会话 ID |
| `{{sys.timestamp}}` | 当前时间戳 |
| `{{sys.workflow_id}}` | 当前 Workflow ID |
| `{{sys.workflow_run_id}}` | 当前运行 ID |

## 12. 条件路由语法参考

| 表达式 | 效果 | 示例场景 |
|--------|------|---------|
| `status=="ok"` | 成功后跳转 | 架构设计通过 → 跳到部署 |
| `status=="failed"` | 失败后跳转 | 代码生成失败 → 跳到修复阶段 |
| `result.pass_rate > 0.8` | 通过率超 80% | 测试通过率很高 → 跳过手动审查 |
| `result.pass_rate < 0.5` | 通过率低于 50% | 测试大面积失败 → 跳到回退阶段 |
| `error is not None` | 有错误 | 任何错误 → 跳到告警/通知阶段 |
| `result.score >= 90` | 打分 ≥ 90 | 评估高分 → 直接合并 |
| `status=="ok" and result.pass_rate > 0.8` | 复合条件 | 成功且高分 → 自动部署 |
